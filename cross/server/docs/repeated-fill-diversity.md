# Разнообразие повторного заполнения

12 октября 2026: по три прогона каждого из выпусков 77 (56 шаблонов) и 78
(96 шаблонов), текущий рабочий CSP+MAC. Контекст геометрии, словаря, настроек
и исторической статистики загружается один раз перед тремя прогонами. Состояние
использованных слов/определений перед каждым новым прогоном очищается.
Статистика не записывается в базу, выпуски и задания не изменяются.

Отдельно проведены три прогона с экспериментальным `shuffle=true` в probe и
разными seed. Это только параметр benchmark-скрипта, не изменение production.
Для каждого режима проверено 456 заполнений; суммарно **912/912 успешно**,
без повторов внутри сетки и между шаблонами одного выпуска.

## Текущий режим

Диапазоны получены по трём попарным сравнениям прогонов 1–2, 1–3, 2–3.

| Набор | Полностью одинаковые заполнения | Одинаковые слова в тех же слотах | Совпадение набора слов выпуска |
| --- | ---: | ---: | ---: |
| 56 | 18–25 из 56 | 45.6–57.8% | 60.3–67.5% |
| 96 | 0–1 из 96 | 6.0–8.0% | 62.9–63.6% |

Таким образом, повторное заполнение **уже может быть другим**, но не каждое
отдельное заполнение гарантированно отличается. Слова также могут повторяться
в другом шаблоне или в другом слоте следующего запуска: это отличается от
дублей внутри текущего выпуска.

Текущий probe отключает перемешивание и часто решает сетку до основного поиска,
где перемешивание включено. Несмотря на это, MAC может идти разными путями:
`build_cross_data` строит порядок пересечений обходом Rust `HashMap`, а первый
найденный конфликт меняет веса dom/wdeg. Дополнительно `build_components`
обходит соседей через `HashSet`, а `remap_slots` перенумеровывает слоты в этом
порядке; это потенциально влияет на выбор равноприоритетных слотов и у DLX.
Поэтому отключённое перемешивание не
означает строго воспроизводимого заполнения. Порядок обхода HashMap произволен
([документация Rust](https://doc.rust-lang.org/std/collections/struct.HashMap.html)).
Связь этого порядка с разнообразием — вывод из кода, не отдельный эксперимент,
изолировавший все источники вариативности. Один seed пока не следует трактовать
как гарантию побайтового воспроизведения CSP на разных вызовах.

## Эксперимент: перемешивание probe

Перемешиваются только равноприоритетные варианты по текущему порядку ранжирования;
словарь, ограничения, приоритеты использования и бюджеты остаются прежними.

| Набор | Полностью одинаковые заполнения | Одинаковые слова в тех же слотах | Совпадение набора слов выпуска |
| --- | ---: | ---: | ---: |
| 56 | 1–3 из 56 | 24.2–31.4% | 44.9–48.8% |
| 96 | 0 из 96 | 6.3–8.2% | 63.1–63.6% |

На малом наборе улучшение заметно; на большом наборе дополнительного выигрыша
в разнообразии почти нет. По три прогона недостаточно для универсального вывода.
Контекст для двух режимов загружался отдельно, каждый затем фиксировался на три
прогона; новые seed и внутренний порядок графа тоже влияют на выбор траектории.

| Набор | Чистый поиск: текущий режим | Чистый поиск: эксперимент | Средняя прежняя частота: текущий / эксперимент |
| --- | ---: | ---: | ---: |
| 56 | 0.880–0.888 с | 0.853–0.885 с | 74.33–74.84 / 74.40–74.95 |
| 96 | 2.295–3.048 с | 2.940–3.228 с | 73.33–73.60 / 73.37–73.50 |

Баланс сопоставим. На 96 шаблонах эксперимент немного медленнее в этом небольшом
замере, хотя абсолютная разница — доли секунды. Полностью новый набор ответов
между запусками не гарантируется и не всегда возможен: в этом наборе 650
трёхбуквенных слотов, а выбранный словарь содержит 721 уникальное трёхбуквенное
слово. Два выпуска с 650 уникальными такими ответами неизбежно разделяют минимум
**2×650−721 = 579** трёхбуквенных слов, даже при идеальном разнообразии.

## Воспроизведение

```sh
pnpm run test:fill-batch-solver-comparison /private/tmp/megacross-repeat-current.json --production-defaults --engine=csp --repeats=3
pnpm run test:fill-batch-solver-comparison /private/tmp/megacross-repeat-shuffled.json --production-defaults --engine=csp --repeats=3 --randomize-probe
```

Сравниваются слова по стабильному `slotId`, а не текст определений или картинки.
Отдельно сравниваются множества слов независимо от их позиции. Если сетка не
заполнена или число слотов отличается, она не включается в знаменатель; таких
исключений в этих прогонах нет. JSON-отчёты содержат все попарные сравнения и
статистику каждого прогона. Unit-тесты проверяют метрики на одинаковых,
переставленных, частично совпадающих и незаполненных вариантах.

Для управляемой новизны можно отдельно внедрить перемешивание probe и проверку
хеша результата против предыдущего заполнения. Чтобы seed стал гарантированно
воспроизводимым, нужен стабильный порядок графа. Ни одно из этих изменений в
рабочем решателе в рамках данной проверки не выполнялось.

## Дополнение: повторные заполнения DLX

По запросу выполнено ещё три прогона текущего DLX на тех же двух наборах,
с фиксированным контекстом для каждой тройки. Настройки production: `shuffle=true`
в основном поиске, `shuffle=false` в probe, 200000 узлов, два перезапуска,
`cost`-балансировка. Движок приложения по умолчанию не менялся: это только тест.

| Набор | Полностью одинаковые заполнения DLX | Одинаковые слова в тех же слотах | Совпадение набора слов |
| --- | ---: | ---: | ---: |
| 56 | 9–11 из 56 | 31.0–39.1% | 50.9–55.9% |
| 96 | 0–1 из 95–96 успешно сопоставленных | 5.2–7.0% | 62.2–63.3% |

DLX тоже выдаёт разные заполнения. На малом наборе в этих прогонах различий
больше, чем у обычного CSP (18–25 полных совпадений), но меньше, чем у CSP с
экспериментальным перемешиванием probe (1–3 совпадения). На большом наборе
разнообразие обеих стратегий близко; три прогона не доказывают общего рейтинга.
Контексты DLX и предыдущих CSP-экспериментов загружались в отдельных процессах,
а затем фиксировались для трёх повторов каждой стратегии.

| Набор | Заполнено по прогонам | Повторные использования между шаблонами по прогонам | Чистый поиск |
| --- | --- | --- | --- |
| 56 | 56/56, 56/56, 56/56 | 0, 0, 0 | 13.341, 11.519, 13.708 с |
| 96 | 96/96, 95/96, 96/96 | 21, 34, 31 | 172.721, 189.945, 155.899 с |

Во втором большом прогоне `17.fsh` остановился с `aborted (maxNodes)`, а не с
доказанным UNSAT. Эта сетка исключена из соответствующих попарных знаменателей.
Итого DLX успешно заполнил **455/456** попыток; повторов внутри отдельной сетки
нет. Повторы между сетками возникли после разрешённых fallback-ослаблений,
максимум два использования одного слова в выпуске. CSP в предыдущих текущих
прогонах заполнил 456/456 и не потребовал этих повторов.

Средняя историческая частота выбранных слов DLX: 74.57–74.90 на наборе 56,
73.86–73.99 на наборе 96. Баланс сопоставим по масштабу, но больший набор DLX
получился существенно медленнее и менее стабилен по успешности/повторам.

```sh
pnpm run test:fill-batch-solver-comparison /private/tmp/megacross-repeat-dlx.json --production-defaults --engine=dlx --repeats=3
```

JSON содержит все 456 попыток, выбранные слова, ошибки и шесть попарных сравнений.
Задания, публикации, файлы выпуска и статистика использования не изменялись.

## Включение перемешивания только для CSP

После согласования включено перемешивание в рабочем CSP probe. API передаёт
сохранённую настройку `shuffle`; CSP использует её (по умолчанию true), явное
`shuffle=false` отключает перемешивание. CLI CSP probe также учитывает `-s` /
настройку перемешивания. Для DLX probe перемешивание принудительно остаётся
выключенным, даже если в общий helper передать `shuffle=true`. Основной DLX
поиск, его прежние настройки и балансировка не менялись.

Выполнено два контрольных цикла по три прогона каждого набора уже через рабочий
helper, без экспериментального `--randomize-probe`. Итого **912/912 заполнений
успешны**. В первом цикле на наборе 96 было 0 / 6 / 0 повторных использований
между шаблонами после разрешённого fallback; во втором цикле — 0 / 0 / 0.
Внутри отдельных сеток повторов не было ни в одном цикле. Поэтому включение
shuffle само по себе не гарантирует абсолютного отсутствия fallback-повторов.

Результаты последнего цикла:

| Набор | Полностью одинаковые заполнения между прогонами | Одинаковые слова в тех же слотах | Чистый поиск по трём прогонам |
| --- | ---: | ---: | ---: |
| 56 | 0–3 из 56 | 26.0–33.6% | 0.861 / 0.855 / 0.863 с |
| 96 | 0–1 из 96 | 6.0–8.5% | 2.586 / 3.512 / 2.702 с |

Средняя историческая частота — 74.39–74.80 и 73.37–73.56 соответственно, то есть
баланс остаётся сопоставимым. Все шесть партий последнего цикла без дублей
между шаблонами. Тесты также отдельно проверяют запрет нового shuffle для DLX,
отключение shuffle в CSP и передачу seed. Пройдены 22 связанных unit/API теста,
TypeScript и lint обоих проектов. Локальный backend перезапущен.

```sh
pnpm run test:fill-batch-solver-comparison /private/tmp/megacross-repeat-enabled-csp-only.json --production-defaults --engine=csp --repeats=3
```

В JSON `randomizeProbe=false` обозначает отсутствие **тестовой подмены**,
а `probeShuffle=true` в сводке — фактическое рабочее перемешивание. Счётчики
использования и содержимое выпусков контрольные прогоны не изменяли.
